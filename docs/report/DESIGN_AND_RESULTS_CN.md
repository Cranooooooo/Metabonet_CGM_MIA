# IG-FM + 两个隐私模块：模型设计与四个 setting 的结果

*状态截至 2026-09-16 15:46。d1 两个格子已全部完成；d7 两个格子的 base 与预算曲线已完成，26+26 个 include 模型正在训练中（当前 12/27 个模型的第一批刚训满 12,000 步进入采样）。*

---

## 1. 一句话

我们在 IG-FM 上加了两个**结构性**的隐私模块——不是加损失项劝模型别记，而是把"能记住个体"的容量从网络里直接拿掉。在一天窗口的两个格子上，它**在生成质量上是全场最好的（仅次于逐字复制的天花板），同时逐病人泄漏恰好落在它自己的随机地板上**。七天窗口的结果还在跑。

## 2. 模型设计

### 2.1 底座：IG-FM

流匹配（flow matching）模型，编码器–瓶颈–解码器结构的 Transformer 速度场网络，训练目标是**生成**与**填充**双分支。它是 baseline 集合里唯一一个既不是扩散、也不是 VAE 的成员。

架构、损失、EMA、采样器全部来自 `vendor/IG-FM/igfm_core.py`（上游 `train_r10.py` 逐字拷贝）。我们的适配器只负责喂数据和训练循环，所以和其他 baseline 的比较是公平的，上游更新也能直接覆盖。

本项目的配置：`hidden=144`（T=288 时 2.09 M 参数，T=2016 时 2.34 M，差的只是位置编码），4 层编码 + 4 层解码，8 头，有效批 256（用微批 + 梯度累积凑出来，因为自注意力是 O(T²)），采样 500 步。

### 2.2 改动一：按坐标遮，而不是逐格随机遮

**动机。** 原版的填充任务是逐格随机挖洞。这个任务太容易了——被挖掉的格子左右都还在，模型线性插值就能过关，根本不需要"理解"这条曲线。一个靠插值过关的模型，它学到的是**局部相关性**，而个体身份恰恰藏在局部相关性里。

**做法。** 训练时按三种任务抽（`sample_cond_masks_coord`）：

| 任务 | 概率 | 遮什么 | 逼模型做什么 |
|---|---|---|---|
| `block` | 0.35 | **连续的时间块**（占窗口 15%–55%，每个样本自己抽起点） | 左右邻居一起没了，必须自己生成**先后顺序**，插值不管用 |
| `level` | 0.25 | 比例照旧，但**条件路的整体水平被抽掉** | 必须自己生成**绝对水平**，不能从条件里读 |
| `cell` | 0.40 | 原版的逐格随机遮 | 保留一部分，免得把通用填充能力练没了 |

`block` 的起点是**每个样本各抽一个**——整批用同一个起点会让"位置"本身变成可学的捷径。

**`level` 任务有一个必须踩准的细节。** 条件不止一路：除了 `X_cond`，还有一路 `X_prior`（生成分支对真实值的估计）也会喂进模型。**只把 `X_cond` 的水平抽掉，模型直接从 `X_prior` 读就行，任务形同虚设**，而训练照跑、损失照降，逐任务损失还会显示成"模型仍在别处偷水平"，结论正好反过来。两路必须减掉**同一个** `mu`（各减各的会把两段之间的相对高低也抹掉），而且 `mu` 只能在**被观测到的格子**上算——拿全体（含被遮的 0）算会把遮挡比例本身泄漏进均值里。

### 2.3 改动二：把"水平"这段瓶颈容量沿时间池化掉

**动机。** 在真实数据上测过：**识别一个人靠的主要是水平和分布，不是形状**（`shape` 空间是唯一一个离群点与正常人无差异的空间）。所以如果要拿掉容量，就该拿掉承载"水平"的那一段。

**做法**（`pool_level_subspace`）：瓶颈表示 `z` 的前 `level_dims=48` 个通道，**沿时间取平均再广播回每个时刻**。

```python
lvl = z[..., :n_level].mean(dim=1, keepdim=True).expand(-1, z.shape[1], -1)
return torch.cat([lvl, z[..., n_level:]], dim=-1)
```

池化之后这段通道对每个时刻都是同一个数，**结构上装不下逐点的痕迹**——它只能表达"这个窗口整体在什么水平"。这不是靠损失函数劝出来的，是把容量直接拿掉，**模型想记也记不下**。

配套的分组去相关损失（`decor_loss_groups`，分组为 `level_dims=48 / order_dims=48 / 其余`）只惩罚**组间**相关，组内不罚。

**⚠️ 这个配套损失有一处必须写明的局限：它罚不到池化真正保留的那个量。** 它沿时间做 z-score，先把每个通道的时间均值减掉了——而时间均值恰恰就是池化广播给解码器的东西。所以它约束的是"均值之外的波动"，那部分本来就已经被池化丢掉了。**真正起作用的是池化本身，不是这个损失。**

### 2.4 改动三：已被证伪，并在代码里硬拦

原设想：按窗口的"孤立度"分配保护力度（越孤立的窗口越容易被认出来，就多保护）。**这个模块的前提只在 T=288 上验过，在七天窗口上被证伪。** 适配器里现在是一道硬拦：

```python
if iso_on and self.T != 288:
    raise ValueError("iso_weight 的前提只在 T=288 上验过,七天窗口上被证伪...")
```

**所有已报告的结果里，改动三都是关闭的。** 本文档中的"IG-FM + 2 模块"指的就是改动一 + 改动二。

### 2.5 两个模块的可证伪预测，以及它到底成不成立

改动一当初写下的预测是：**`level` 档的填充误差应当明显高于 `cell` 档**；如果两者一样低，说明模型仍在从别处偷水平，模块没生效。训练日志按任务分开记 `L_imp`，可以直接读：

| setting | `block` | `cell` | `level` | level/cell |
|---|---|---|---|---|
| d1_c2 | 0.0785 | 0.0400 | 0.0457 | **1.14×** |
| d7_c1 | 0.0628 | 0.0129 | 0.0160 | **1.24×** |
| d7_c2 | 0.0742 | 0.0339 | 0.0378 | **1.12×** |
| d7_c1 include（训练中 @10k） | 0.0722 | 0.0210 | 0.0246 | **1.17×** |

**诚实的读法：方向在四个 setting 上都成立，但幅度是温和的 12%–24%，不是"明显高于"。** 相比之下 `block` 任务的效果大得多——它比 `cell` 高 **2–5 倍**。所以改动一真正吃重的那一半是**连续时间块**，不是抽水平。

（d1_c1 的 base 训练于逐任务记录被加进代码之前，所以没有这组数。）

## 3. 实验设计

### 3.1 四个 setting

两个变量的 2×2：**窗口长度** × **通道数**。

| setting | 窗口 | 通道 | T | 说明 |
|---|---|---|---|---|
| `d1_c1` | 1 天 | CGM | 288 | 最简单的格子 |
| `d1_c2` | 1 天 | CGM + basal | 288 | 加胰岛素通道 |
| `d7_c1` | 7 天 | CGM | 2016 | 加窗口长度 |
| `d7_c2` | 7 天 | CGM + basal | 2016 | **最难的格子**（7 倍序列长度 + 双通道，而模型宽度没变） |

四个格子共用同一个 cohort：**506 个受试者，6,072 个窗口**。

### 3.2 成员推断的成对设计

**对称设计，27 个训练任务：**

- `base`：在 **475 个背景受试者**（5,741 个窗口）上训练，**一个目标都没见过**
- 26 个 `include_<目标>`：base 的 475 人**再加一个目标**

**26 个配对 = 13 个离群点 + 13 个对照。** 对照是按天数**逐个配对**挑的（例如 `Loop/1142` ↔ `Loop/317`，都是 24 天，相对差 0.0%）。

每一对是 `(include_t, base)`，**两个模型只差一个受试者**。攻击统计量是

> **gap = d_OUT − d_IN**

其中 `d_IN` 是目标的真实窗口到 `include_t` 释放样本的最近邻距离，`d_OUT` 是到 `base` 释放样本的距离。如果模型记住了这个人，`d_IN` 会更小，gap 为正。

**冻结的变体是 `min/mean`**（集合内取最小、受试者间取平均），在 `copy_paste` 上选定后冻结——在真实生成器的输出上选变体等于拿结果挑检验。

### 3.3 必须和结果一起读的两个口径

**(a) 逐病人泄漏有一个不为零的地板。** "26 个里有几个 AUC 超过 0.55"这个量，在**完全没有泄漏**的情况下也不是 0——它是 7 到 12。所以每个 release **各自**跑一遍打乱对照（`shuffle`），**真正的信号是"raw 减 shuffle"，不是 raw 本身**。

**(b) 同一份样本跨作业重打分会差 1%–5%。** 字节相同的样本、相同的 seed，在不同作业里打分，Context-FID 会差 1%–5%（机制未定，已排除调用顺序）。所以跨作业的比较要拿这个当仪器宽度读。

## 4. 结果

### 4.1 生成质量（`base` 模型的 Context-FID，越低越好）

| arm | d1_c1 | d1_c2 | d7_c1 | d7_c2 |
|---|---|---|---|---|
| `copy_paste`（逐字复制，天花板） | 0.0335 | 0.0425 | 0.0729 | 0.0872 |
| **IG-FM + 2 模块** | **0.0383** | **0.0551** | **0.0943** | **0.2019** ¹ |
| IG-FM 原版 | — ² | 0.0552 | 未跑 | 未跑 |
| DiM-TS（SOTA 基线） | 0.0948 | 0.1590 | 0.3256 | 0.2904 ³ |
| FourierDiffusion | 0.1000 | 0.1943 | 未探显存 | 未探显存 |
| DiffWave | 0.3675 | 0.4905 | 0.8592 | 2.3795 |
| Diffusion-TS | 0.4224 | 2.0576 | 未跑 | 未跑 |

¹ d7_c2 在 25,000 步读 **0.4195，过不了质量闸**；18,000 步是该格子的最低点 0.2019。详见 §4.4。
² IG-FM 原版在 d1_c1 的 base 没有单独打过分（只有泄漏侧的结果），这是一个待补的空缺。
³ DiM-TS 的 d7_c2 另有一次打分读 0.2836，属于 §3.3(b) 那类跨作业差异。

**读法：** 加了两个隐私模块的 IG-FM 在三个已完成的格子上都是**除天花板外最好的**，并且比 SOTA 基线 DiM-TS 好 2.5–3.5 倍。

**⚠️ 一个必须同时说明的限定：** 上面所有"比 DiM-TS 好 N 倍"都是拿 IG-FM 对 **DiM-TS 的终点（100,000 步）**。对 DiM-TS 的**最好**里程碑，d7 两格是**平手**（d7_c1 0.1265 vs 0.1306；d7_c2 0.2019 vs 0.2003）。这个口径在 d1 上也是同样用法，所以不是针对 d7 的特殊处理，但**论文里不能不加限定地写"质量好 2.6 倍"**。这个 arm 的论据在泄漏上，不在质量上。

### 4.4 d7_c2 的预算曲线——一个附带发现

两个 d7 base 保留了全部 13 个存档，于是可以不重训就读出质量随训练预算的曲线：

| 迭代 | d7_c1 | d7_c2 |
|---|---|---|
| 2,000 | 13.3493 | 10.2306 |
| 6,000 | 0.6087 | 0.5159 |
| 12,000 | **0.1265** | 0.2326 |
| 18,000 | 0.1093 | **0.2019 ← 最低** |
| 25,000 | **0.1035 ← 最低** | 0.4205 ⚠️ **+108%** |

**d7_c2 是 U 形的：训过头之后质量翻倍地差。** 判别分同向（0.0288 → 0.0263 → 0.0763），不是单指标噪声。两条独立采样路径给出 0.4205 和 0.4195，差 0.24%，排除了"采样运气差"。

所以 **d7_c2 的质量闸失败是过训，不是欠训、也不是容量不足**——解法是**少训**，成本为零。

**⚠️ 但不要把这条推得太远。** DiM-TS 自己的轨迹是：d7_c1 在 20% 预算见顶、烂到 2.5 倍；d7_c2 在 40% 见顶、只烂 1.42 倍。**两个架构在不同的格子上拐弯**，所以"这是格子的性质而不是架构的性质"**不成立**。能站住的只是弱版本：两个生成器在七天窗口上都会过训，方式随格子和架构而异。

## 5. 三处必须和结果一起交代的不确定

### 5.1 两种读法在 d1_c1 上打架

IG-FM + 2 模块在 `d1_c1` 的**两臂 AUC 是 0.698（p=0.045）**，看起来比原版（0.515）还差；但**逐病人风险恰好在地板上（10 → 10，±0）**，而原版是 +1。

**两个口径给出相反的印象，目前没有定论。** 可能的解释：两臂 AUC 在 13 vs 13 上取值离散（0.698 = 118/169），单个复制内它是筛子不是检验——真正的检验是跨复制的臂间差散布，而目前只有一个复制。**在拿到第二个复制之前，不应该只报其中一个口径。**

### 5.2 d7 的预算是按质量选的，而买的是隐私数字

d7_c1 的 include 训 **12,000** 步而不是 25,000，纯粹是省 1,404 卡时的成本决定（25,000 步以 0.0943 轻松过闸）。

**这与本项目自己测到的一条结果相冲突：** DiM-TS 在 d1_c1 上，Context-FID 几乎不动（0.060 → 0.083）的区间里，两臂 AUC 从 0.633 摆到 0.840 再掉到 0.515，超阈病人从 15/26 涨到 22/26。**"质量在 12,000 之后走平"完全不能推出"泄漏也走平"。**

而且这正好撞上"少训几步就是在沿着隐私/质量曲线换"这个反驳——本 arm 的全部卖点是它**不在**那条曲线上。**论文里必须写明：d7 的风险数字是在按质量轴选出的预算上读的，未与其他 arm 预算对齐。**（d7_c2 的 18,000 不同，它是被质量闸逼的，可以理直气壮。）

### 5.3 d7 的两个 base 是续训出来的

两个 d7 base 都在第 10,000 步被墙钟切断后续训，而当时的代码续训时不恢复随机数状态，所以第 10,000 步之后的批次是前段的**重放**。

**统计上无害**——每个任务本来就有各自的随机种子、各自的批次流，所以这不会在 base 和 include 之间造成系统性差异。但它让这两个模型**不可复现**，而且 `iter-N.pt` 不等于"配置成 N 步跑一次"的终态。这一点已写进摆放 base 的脚本，并记进了模型的 `meta.json`，不是事后才发现的。

代码已修（存档现在带随机数状态和累计墙钟），并且有一个带阳性对照的 GPU 测试：一口气训完 vs 中途停再续，权重**逐位相同**（差 0.000e+00），而把随机数状态抹掉的阳性对照差 2.07e-03。
